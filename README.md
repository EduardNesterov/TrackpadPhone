# TrackpadPhone

iPhone как трекпад для Mac. Локально по Wi-Fi, без облака.

Архитектура и обоснования решений — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Состояние

| | |
|---|---|
| `TrackpadKit/TrackpadProtocol` | кодек протокола |
| `TrackpadKit/TrackpadInput` | распознавание жестов, ускорение, инерция |
| `TrackpadKit/TrackpadProtocol` | плюс пейринг: QR-код, ключ в Keychain, ChaCha20-Poly1305 |
| `Spike/mac-receiver/` | приём по UDP → CGEvent. Выбрасывается после M1 |
| `Spike/fake-phone.py` | тестовый телефон: гоняет Mac-часть без iPhone |
| `Apps/TrackpadPhoneiOS/` | поверхность касаний во весь экран, альбомная ориентация |

Ещё нет: медиа-пульта (после v1).

## Отдать другому человеку

Одностраничная инструкция на английском, которую можно просто переслать вместе с папкой:
[`docs/GETTING-STARTED.md`](docs/GETTING-STARTED.md). Там обе половины, пейринг и раздел
про то, почему нужен Xcode.

Коротко: Mac-часть собирается `./scripts/build-mac-app.sh` и подписывается сама (личность
разработчика, если она есть, иначе ad-hoc). Телефонная — `./scripts/install-phone.sh`:
находит подключённый iPhone сам, подставляет **чужую команду и свой bundle id**, если
машина не авторская (тот же идентификатор со свободным Apple ID второй раз не
регистрируется), собирает и ставит.

Передавать — не папку целиком: в ней 676 МБ сборочного мусора и `.app` с твоей подписью.
Чистая копия ровно из того, что в репозитории:

```sh
git archive --format=zip -o ~/Desktop/TrackpadPhone.zip HEAD
``` Бесплатный Apple ID даёт семь дней,
дальше запустить скрипт заново; пейринг это переживает, он в Keychain.

Единственный путь, при котором человеку вообще не нужен Xcode, — платный аккаунт и
TestFlight: он ставит по ссылке, сборка живёт 90 дней.

## Пейринг

Первое подключение — один раз, по QR. На Mac: значок в меню → «Показати код для телефона…»;
на телефоне: «Сканувати код». Дальше телефон находит Mac сам по Bonjour, адрес вводить негде
и незачем.

Курсора может не быть в тот самый момент, когда нужно открыть окно кода (неспаренный телефон
ещё не двигает мышь). Поэтому есть путь без указателя — открыть Терминал через ⌘Space и:

```sh
osascript -e 'use framework "Foundation"' \
  -e 'current application'"'"'s NSDistributedNotificationCenter'"'"'s defaultCenter()'"'"'s postNotificationName:"TrackpadPhone.pair" object:(missing value)'
```

Пункт меню «Приймати лише спарений телефон» по умолчанию **выключен**: пока он выключен,
порт слушает всех, как раньше. Включать после того, как спаренный телефон заработал.

## Жесты

| Пальцы | Действие | Как реализовано |
|---|---|---|
| 1 — вести | курсор | кусочно-линейная кривая ускорения + субпиксельный остаток |
| 1 — тап | клик | двойной и тройной считаются через `ClickState` |
| 1 — тап, затем вести | перетаскивание | «полтора тапа», как в macOS |
| 2 — вести | скролл | фазы began/changed/ended + инерция на стороне Mac |
| 2 — тап | правый клик | |
| 2 — развести/свести | зум | ⌘+скролл |
| 3 — вверх | Mission Control | запуск `Mission Control.app` |
| 3 — влево / вправо | назад / вперёд | ⌘[ / ⌘] |

Клик, перетаскивание и сработавший жест отдаются **вибрацией на телефоне** (CoreHaptics).
Экран во время работы пустой, так что это единственное подтверждение, что поверхность
вообще что-то поняла. Решение принимает Mac — только он знает, что клик состоялся, — поэтому
отдача приходит через один круг по сети; при RTT около 20 мс это ещё ощущается связанным
с движением. Выключается тумблером в настройках на телефоне.

### Чего macOS не позволяет

Измерено на macOS 26, а не предположено. Синтетические нажатия **доходят** до потока событий
с верным флагом модификатора (слушатель это подтвердил), и обычные программные сочетания на
них срабатывают — ⌘N в пробнике открыл окно Finder. Но **системные сочетания
(symbolic hotkeys) система отвергает**: ⌃↑ был послан пятью способами — флаг на событии,
модификатор как обычная клавиша, модификатор как `flagsChanged`, в двух точках вставки
событий — и не сработал ни разу, тогда как запуск `Mission Control.app` в том же прогоне
срабатывал всегда.

Отсюда:
- **Mission Control** работает — через запуск приложения.
- **Переключение рабочих столов и App Exposé недостижимы.** Публичного пути нет: приложения
  для них не существует, а нажатия система не принимает. Боковые свайпы переназначены на
  «назад/вперёд», что полезно и работает.

Пробник живёт в приложении (`--- probe start ---` в `/tmp/trackpadphone.log`), так что опыт
можно повторить, если правила в новой macOS изменятся.

### Ускорение курсора

Сделано по тому, к чему пришли [libinput](https://wayland.freedesktop.org/libinput/doc/latest/pointer-acceleration.html)
и [Windows](https://blog.codinghorror.com/mouse-ballistics/) — не формула, а **кусочно-линейная
кривая по узлам**. Формула вида `base + k·v` не умеет главного: опускаться **ниже единицы** на
медленном движении, а именно эта зона и даёт точность (libinput замедляет до 0.3×).

Кривая в `AccelerationCurve.knots`, скорость в мм/с → безразмерный множитель:
замедление 0.4× у нуля, единица около 35 мм/с, подъём до 5.2× и потолок. Множитель отделён от
чувствительности, поэтому ползунок не сдвигает точку, где включается ускорение.

Скорость меряется **скользящим окном**, а не по одному кадру (кадр на 120 Гц — это доли
миллиметра, шум квантования один дал бы разброс в разы). Окно схлопывается, когда движение
меняет характер:

- **разворот** — иначе скорость, набранная вправо, ещё сидит в оценке, когда палец пошёл влево,
  и курсор улетает; это и есть перелёт на коррекции;
- **рывок** — бросок после медленного наведения должен получить высокий множитель сразу, а не
  когда окно домножит медленную часть.

После схлопывания скорость считается **неизвестной**, а не мгновенной: разворот почти всегда
коррекция, ей нужна точность. Побочно это отсекает дрожание — оно разворачивается каждый кадр
и до двух отсчётов не доживает.

Пороги и коэффициенты — в `GestureConfig`, все в одном месте, потому что подгоняются на ощупь.

## Запуск

### 1. Mac

Собрать один раз:

```bash
./scripts/build-mac-app.sh
```

Дальше `dist/TrackpadPhone.app` открывается двойным кликом (можно перетащить в
`/Applications`). Окна нет — значок появляется в строке меню, там же состояние, адрес для
телефона, ползунки скорости и «Вийти».

**Нужно разрешение Accessibility**, иначе ничего не будет двигаться:

> Системные настройки → Конфиденциальность и безопасность → Универсальный доступ

Пункт для этого есть прямо в меню значка, пока разрешение не выдано.

Почему именно `.app`, а не бинарник из терминала: macOS привязывает разрешение к подписи
запущенной программы. У бинарника из шелла «программа» — это **терминал**, поэтому
разрешение тянется за тем терминалом, которым вы случайно воспользовались. Скрипт
подписывает бандл вашим Apple Development сертификатом — подпись стабильная, значит
разрешение выдаётся один раз и переживает пересборки. (Ad-hoc подпись меняется при каждой
сборке, и macOS считает каждую сборку новой программой.)

### Отладочный CLI

Тот же приёмник в консоли, с подробным выводом — удобно, когда жест ведёт себя не так:

```bash
cd Spike/mac-receiver && swift run mac-receiver --debug
```

Печатает число контактов и каждое распознанное событие. Флаги: `--sensitivity`,
`--scroll-gain`, `--invert-scroll`, `--port`.

Порт один и тот же (51888), поэтому приложение и CLI одновременно не работают — второй
сообщит «Address already in use».

### 2. iPhone

Сборка и установка без Xcode:

```bash
xcodebuild -project TrackpadPhone.xcodeproj -scheme TrackpadPhoneiOS \
  -destination 'generic/platform=iOS' -allowProvisioningUpdates build
```

```bash
xcrun devicectl list devices
```

```bash
xcrun devicectl device install app --device <UDID> \
  ~/Library/Developer/Xcode/DerivedData/TrackpadPhone-*/Build/Products/Debug-iphoneos/TrackpadPhone.app
```

**Первый запуск потребует доверия на самом телефоне**, иначе система откажет с
`invalid code signature … profile has not been explicitly trusted`:

> Настройки → Основные → VPN и управление устройством → приложение разработчика → Доверять

Дальше — ввести адрес Mac, нажать Connect, водить пальцем.

Профиль бесплатного аккаунта живёт **7 дней** (текущий — до 13 августа 2026), потом
приложение надо переустановить той же командой.

#### Подводный камень: DEVELOPMENT_TEAM

Team ID — это поле **OU** в сертификате, а не значение в скобках после имени. Значение в
скобках относится к самому сертификату, и подстановка его в `DEVELOPMENT_TEAM` даёт сбивающую
с толку ошибку `No Account for Team`, которая выглядит как отсутствие аккаунта в Xcode:

```bash
security find-certificate -c "Apple Development" -p | openssl x509 -noout -subject
```

`/UID=…/CN=Apple Development: почта (ЭТО НЕ TEAM ID)/OU=ВОТ TEAM ID/O=…`

### Проверка Mac-части без телефона

```bash
python3 Spike/fake-phone.py 127.0.0.1
```

Синтезирует свайп, дубликат, устаревший кадр и тап. Пакеты собираются прямо по спецификации,
а не моим же Swift-кодеком, поэтому расхождение форматов — настоящая находка, а не общий баг.

## Что читать в выводе приёмника

```
  61 fps   gap p50  10.5 ms   p95  10.7 ms   lost 0   discarded 2
```

- `lost` — дыры в нумерации, то есть **реальные потери сети**. Вот за этим и следим.
- `discarded` — дубликаты и кадры не по порядку, отброшенные намеренно. Норма, не проблема.

Эти два числа специально разведены: смешанные, они превращают исправную работу дедупликации
в видимость сетевых потерь.

RTT показывает **телефон** — только у него оба штампа времени на одних часах, поэтому
синхронизация часов с Mac не нужна и не делается.

## Ориентир по задержке

Касание 8 мс + сеть 2–15 мс + обработка <1 мс + композитор 8–16 мс ≈ **20–40 мс**.
Ниже ~50 мс ощущается мгновенным, выше — курсор заметно тянется за пальцем.
